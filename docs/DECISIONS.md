## Project and process

**D1. GitHub is the authoritative record (2026-11-03).** Humans, Claude and ChatGPT/Codex all work from the docs in this repository, not from chat history. `AGENTS.md` and `CLAUDE.md` direct each agent to read the shared docs first; every substantial PR updates docs and `STATUS.md`. *Rejected:* keeping context in per-agent memory or chat summaries (lost between sessions, diverges between agents).

**D2. No application accounts (existing).** Access is Vercel Authentication plus a server-only database key; RLS rejects requests without it; `noindex` and `no-store` headers. *Reason:* personal tool, minimum attack surface, fast mobile use. *Consequence:* writes from batch jobs use a service-role key that only exists in the owner's local environment.

**D3. Schema changes only through migrations; applied migrations are immutable (existing, restated 2026-11-03).**

## Data and identity

**D4. Identity is the normalized name; merging requires a reviewed alias (existing).** `lower(trim(name))` is the key. Aliases are rows with a reason and confidence, originals stay searchable. *Rejected:* fuzzy auto-merge (silent wrong merges would corrupt ratings and notes). *Cost:* same-name different people are not separable; audit query 5 measures it.

**D5. Placements are evidence, never wins (existing).** Tournament placements are stored and displayed; they never become match results and do not feed the rating.

**D6. Age group and weight come from division and bracket evidence only (existing).** No exact body weight from a bracket, no birth date from a division, no forced youth grouping for 2020 to 2022 birth years, girls' bands or high school.

## Club analytics and search (2026-11-03)

**D20. Aggregate only confirmed aliases; preserve unknown labels as separate organizations. Initial views expose observed roster size, participation, record, median current wrestler conservative score, top-five strength, and current rating of opponents (explanatory SOS). These metrics are blank when no rating model is active. No inference that a club *developed* a wrestler solely from their appearance on a roster. Historical season rosters use event affiliation, but power ratings are current estimates, never mislabeled as historical backtests.

**D22. Club is chosen from the most recent evidence encountered. Name aliases are based on the reviewed wrestler alias table; do not create new wrestler identity merges by name similarity.

## Rating model (2026-11-03, Claude session; unvalidated on production data)

**D7. Glicko-2 as the baseline.** It is a published, open specification, models uncertainty (RD) natively, grows uncertainty with inactivity without lowering ability, adjusts for opponent strength inside the update, and needs no arbitrary newcomer cap or minimum-match rule. *Rejected:* Elo (no uncertainty), Bradley-Terry/Massey batch fits (harder to explain, no natural recency), and extending the legacy heuristic (ignores opponents). Elo and a smoothed win-rate model are kept as backtest baselines.

**D8. Batch pipeline with immutable versioned models, not a SQL view.** The rating is a sequential filter over time with per-period state; a view cannot express that cleanly, and models need configuration, fingerprints and rollback. Raw matches and old models are never modified. Activation is a status change guarded by a unique partial index.

**D9. Conservative ranking score = rating − k × RD, k = 1.** Simulations with the default curves showed k = 1 lets a strong newcomer rank above a weaker established wrestler, while k = 2 hides most newcomers. Configurable and stored per model; to be revisited with the real backtest.

**D10. Contested outcomes only.** Decisions, major decisions, tech falls and falls are rated. Forfeits, medical forfeits, defaults, disqualifications, no contests and byes are excluded by default and reported; unknown methods are excluded and listed. *Assumption:* production `win_type` values were not inspected. A backtest policy variant measures including DQ/default; policy variants are never auto-adopted.

**D11. Strength of schedule is explanatory only.** It uses opponents' current ratings (hindsight). Feeding it back would double-count, because Glicko-2 already weights opponent strength inside each update.

**D12. Dominance/margin adjustments are experimental and off.** Adopt only if a held-out, paired-bootstrap backtest shows a gain of at least 0.002 log loss per match with the 95% interval below baseline and no meaningful calibration loss.

**D13. One global rating pool; cohort rankings are a view over it.** Cross-age and cross-weight bouts contribute. A bout's two wrestlers share a bracket, so there is nothing to discount per bout and no context-discount variant exists. Cohort rank uses latest evidence per (age group, 10 lb band).

**D14. Walk-forward leakage rule.** Predictions for an event come from the snapshot before the rating period containing the event's first bout; updates apply after the period. Tuning window and held-out confirmation window are separate. *Reason:* same-event and day-two leakage inflates every metric.

**D15. 7-day Monday-anchored rating periods; inactivity as RD growth; tau 0.5.** Standard Glicko-2 guidance (several games per period) and the paper's tau range; the backtest sweeps alternatives. Provisional/developing/established thresholds (RD 120/80) are provisional defaults.

**D16. UI never mixes rating systems.** When a model is active every profile uses it; with none (or the views missing) every profile uses the legacy view. *Reason:* a comparison mixing the two 0 to 1000 scales would be misleading. The 0 to 1000 display is preserved; its meaning changes when a model is active and this is documented.

**D17. Migration 009 is verified in an in-process Postgres (PGlite) with stubbed roles.** No Supabase access from the build environment; the test applies all migrations in order and checks constraints, the single-active rule, RLS wiring and view output. It does not replace applying the migration to a real project and rerunning checks there.

**D16. Do not widen the outcome classifier before the audit runs (2026-11-03, Claude session).** A code review found plausible spellings that `classifyMethod` returns as `unknown`: hyphenated forms (`DEC-OT`, `Dec-SV`, `MD-12`, `Fall-1:23`), a score inside `win_type` after an overtime code (`SV-1 5-3`, `TB-1 3-2`), dotted abbreviations (`T.F.`, `M.D.`), `2OT`, `DQ (unsport)`, `DFLT`, `Med FFT`, `MedFor`, and generic `W`/`WIN` (for these the `result` fallback is not consulted, because it only runs when `win_type` is blank). `Medical Default` classifies as `medical_forfeit` rather than `default`; both are excluded, so ratings are unaffected. Unknowns are already excluded and counted, which is the safe failure. *Decision:* change `outcomes.ts` only for values the audit actually finds, each with a test, rather than guessing a broader grammar (`matches.win_type` is at most 20 characters, which limits the space). Candidate fix if hyphenated forms appear: normalize `-` to a space in `clean()` for the method token while leaving `TF-1.5`-style tokens matching. *Rejected:* pre-emptively adding every spelling (risk of misclassifying a forfeit or default as contested, which would rate a bout that was never wrestled).

**D17. Audit SQL is executed in tests (2026-11-03, Claude session).** `tests/db/match-audit.test.ts` runs `supabase/audits/match_outcome_audit.sql` against the migrated schema in PGlite and checks that it writes nothing and finds seeded duplicates, swapped winner/loser records, multi-club names and unparseable weights. *Reason:* the audit is the evidence for D10 and D16; a syntax error would only be discovered in the SQL editor.

**D18. Outcome classifier stays unchanged; supersedes the open question in D16 (2026-11-03).** The production audit found only F, DEC, TF, MD, FOR, DEF, M FOR, DQ, MFFL, NC and one OTHER1 (a 0-0 bout, correctly excluded as unknown). None of the variant spellings listed in D16 occur, so the hyphen-normalization fix is not applied. *Reason:* changing working code for spellings the data does not contain adds risk without benefit. Revisit if a future import introduces new codes; the calculation report lists every unknown method.

**D19. Do not automatically drop opposite-winner pairs from Flo imports (2026-11-03, verified against raw source rows).** The preliminary audit found 65 opposite-winner pairs under its matching rules. A separate read-only grouping identified 57 such groups, 54 of them with blank round labels. Inspection of source-file and row evidence showed that some are consistent with separate contested matches, although the CSV alone does not prove whether they are rematches or conflicting exports: for example, Bradenton Brawl #1 on 2026-04-11 records Jett Newell beating Noah McCathy by fall and Noah McCathy beating Jett Newell 11–10, in consecutive source CSV rows. Other reverse-direction groups pair a contested result with a forfeit or default, where only the contested result belongs in the rating model. **Do not treat a matching date, event, bracket and opponent pair as proof of a duplicate, and do not delete or suppress both records automatically.** Existing exact same-direction duplicate filtering remains; raw matches stay immutable. Future deduplication must use demonstrable source-level evidence and tests, and report ambiguity instead of quietly removing legitimate rematches. Two regression tests cover these cases. A new, conservative, deterministic dedupe rule can be proposed after inspecting specific duplicate groups, but is not adopted here.

## Validated activation (2026-11-03)

**D23. Adopt daily Glicko-2 with decision winner score 0.8 for the first production model.** Supersedes D15's period default and D12's unvalidated status for this particular variant. The existing one-factor tuning selected daily periods and decision-0.8, then the combined candidate passed the untouched confirmation window: log-loss gain 0.00927 per bout, event-bootstrap 95% interval [-0.01156, -0.00727], calibration improved from ECE 0.02453 to 0.01567. Accuracy 66.17% across 8,146 held-out bouts. Other contested wins remain 1; margins remain off. Keep engine reference defaults unchanged and commit explicit production overrides so future backtests retain a stable reference. Rejected: adopting tuning winners without held-out confirmation; enabling arbitrary margin variants; changing uncertainty labels to make the leaderboard look more certain. See BACKTEST_REPORT.md.

**D24. Activate through the existing restricted atomic SQL function using connected Supabase authorization.** No service key was requested, extracted, logged or added to Vercel. Calculated ratings/history were inserted under a building model, counts and invariants checked, then candidate promotion and `private.activate_rating_model` executed in a transaction. No public write RPC, grants or migrations were needed. Rejected: broadening anonymous permissions or using the CLI's non-atomic two-request activation. Raw match count and outcome checksum were unchanged. D19 remains in force: all candidate rematches are retained, with zero exact-row exclusions on this snapshot.


## Current cohort inference — three distinct events (2026-11-04)
Current age-division and bracket-weight estimates use the three most recent distinct events with 50/30/20 recency weights. Multiple bouts at one tournament count as one event. Within an event, entry evidence outranks observation, derived evidence and match labels. Age division and bracket weight are voted independently. Bracket weights are *entry labels*, not measured bodyweights; competing up does not prove a birth cohort. Global Glicko-2 ratings are unaffected. This is an initial heuristic to validate against actual wrestlers and should not be interpreted as verified age or bodyweight.


**D25. One database authority for current cohorts (2026-11-04).** Supersedes D13's latest-per-historical-cohort rule and the initial TypeScript-only three-event implementation. Search, profile construction, likely pools and active strength rankings read security-invoker `wrestler_cohort_current`. Each wrestler has at most one current age/weight cohort. Normalize event names and group consecutive dates no more than seven days apart into one event; repeated editions separated by longer gaps remain distinct. Use the newest three events (50/30/20); missing dimensions abstain without looking beyond those events. Independently prefer entry, unambiguous observation, derived evidence, then match label. A verified entry weigh-in overrides bracket evidence within its event. Conflicting equal-priority distinct values split that event's vote, never multiplied by bouts. Ties choose the value seen most recently, then the lower numeric value. Named dual/duals events receive half influence for classification only; this is an explicit heuristic, not a validated rating discount. No birth years are inferred from the selected division. Rejected: maintaining SQL and TypeScript implementations that drift; using user-selected filters to change an athlete's score; moving old bracket labels into measured weight. Global Glicko and raw records are unchanged.

**D26. Bound the cohort query plan (2026-11-04).** Full production data exposed a repeated nested join that small migration fixtures did not. Follow-up immutable migrations materialize label/metadata calculations and use a full equality join (labels are a subset of metadata) so PostgreSQL can hash the join despite cardinality underestimates. No materialized data cache, privileged function, or public write permission was introduced.


**D27. Population tiers preserve equal ratings (2026-11-04).** Cohort Tier is computed only in the authoritative security-invoker strength view from the conservative Glicko ordering. For population N, competition rank R and equal-score count T, tier = ceil(10 × (R − 1 + T/2) / N). The midpoint of occupied rank positions keeps tied conservative ratings in one tier. Untied deciles differ by at most one wrestler; ties can make groups uneven or empty. A completely tied population gets Tier 5, not fabricated distinctions. Tiers require at least 20 rated cohort members and unique top support for both inferred age and weight. Tied classification support still uses the existing deterministic current estimate/rank but gets no tier. No existing inference vote, cohort population, strength scale or global rating is changed. Rejected: score intervals; NTILE splitting equal ratings by name; treating provisional rating status as a tier. Provisional/developing/established remain independent.

**D28. Explicit scales and shared presentation (2026-11-04).** Cohort Strength (0–1,000) is always the numerical relative-strength headline; choosing Matchup Likelihood sorting changes order, not that headline's scale. Reusable CohortStanding and GlickoMetrics components serve comparison profiles, ranking lists and existing club rosters. Club aggregate conservative values remain labeled on the raw Glicko scale; they are not normalized across incompatible age/weight groups. Schedule Difficulty is a reference-1,500 expected win percentage, with lower meaning harder, and Average Opponent Glicko Rating is supplementary. Club summaries average the existing reference-expectation formula over recorded opponents; no validated wrestler model or matchup formula is recalculated. Search suggestions currently show classification only, so no strength/tier calculation is added to search.


**D29. Bound schedule/profile reads without cached derived state (2026-11-04).** Production checks exposed numeric exponentiation cost and a filtered-club nested scan over active ratings. Follow-up views compute the existing expectation in double precision (matching JavaScript), materialize active ratings and the participant-rating join once, and keep invoker security. A profile reuses cohort classification returned with its authoritative strength row; only missing/unrated classifications need another read, which occurs separately. Standing read failures are explicit, not false evidence of missing ratings. No service credentials, raised timeout, weakened RLS, duplicated ranking formula or stale cache was introduced.
